# 浮动灵动岛 · 渲染与窗口技术方案（2026-11-24）

**性质**：技术方案，已定方向，未实现。界面依据仍是 `jolu-new.pen` 的 R2-I-00～07（联动与趣味方案），本文只回答「怎么做出来才不像一个装着网页的盒子」。

**已定（鼠鼠 2026-11-24）**：
1. 接受舞台窗口：窗口固定为最大形态尺寸，透明区域鼠标穿透（第 3 节）。
2. 贴边改为「从屏幕边缘长出来」，取代现在的 32px 迷你胶囊（第 5 节）。
3. bot 改用 Rive 实现（第 6 节）。
**涉及代码**：`backend/src/commands/island_window.rs`（`resize_island`）、`backend/src/dock.rs`、`backend/src/island_pointer.rs`、`frontend/src/hooks/useIslandWindowSize.ts`、`frontend/src/components/island/CapsuleIsland.tsx` / `Bot.tsx` / `capsule.css`。

## 1. 现在为什么像盒子

| 现象 | 原因（代码里的位置） |
|---|---|
| 展开 / 收回时边缘被切、卡顿一下 | 原生窗口跟着内容改尺寸：`ResizeObserver` → `resize_island` → `set_size` + `set_position`（`useIslandWindowSize.ts`、`dock::resize_free_centered`）。CSS 在做 0.42s 的弹簧动画，原生窗口却是一步步跳，WebView 的绘制和窗口改尺寸不同步 |
| 阴影只能「留出空间」才有，贴边时干脆不投影 | 窗口多大，能画的范围就多大。AGENTS.md 里「只有展开卡片留投影空间」「贴边不投影」都是在绕这个限制 |
| 「毛玻璃」看起来是一块平的半透明色 | `capsule.css` 用 `backdrop-filter: blur(30px)`，但透明 WebView 里的 `backdrop-filter` 只能模糊网页自己的内容，取不到桌面，所以没有真正的玻璃感；变形时还得关掉它（AGENTS.md「形变期间关闭 backdrop-filter 消除贴边弹出卡帧」） |
| 形变是「换一棵 DOM 树」 | 收缩、展开、停靠三态各是一套 JSX，切换时内容整块替换（`useIslandWindowSize.ts` 的注释写明「会换整棵 JSX 树」），看起来像翻页，不像同一个东西在长大 |
| 动画被打断时会顿一下 | CSS `transition` 被新目标打断时从当前位置重新开始，速度归零；连续触发（请求开始又马上改道）时尤其明显 |
| 多个岛之间没法有动画 | 本体和分身是各自独立的窗口，R2-I-05 的「接力传球」这种跨岛动画在现在的结构里画不出来 |

## 2. 方案总览

按投入从小到大分四层，每层单独有效：

| 层 | 做什么 | 解决 | 投入 |
|---|---|---|---|
| A 舞台窗口 | 窗口固定为最大形态的尺寸，不再跟着内容改；岛在里面自由变形；没有内容的地方鼠标穿透 | 边缘切、卡帧、阴影受限 | 中：后端改窗口与命中检测，前端去掉尺寸同步 |
| B 一个连续的轮廓 | 岛的外形用一条随弹簧变化的路径画出来，内容跟在后面淡入；气泡用「液体分离」的方式从主体里长出来 | 翻页感、打断时顿挫 | 中：前端重写形变层 |
| C 硬件感材质 | 不做假玻璃，改成近乎纯黑的实体表面 + 内高光 + 真实阴影；贴顶时像从屏幕边缘长出来 | 平板半透明的廉价感 | 小 |
| D 单一叠加层（远期） | 每块屏幕一个全屏透明穿透窗口，本体和分身都画在里面 | 跨岛动画、分身内存占用 | 大，风险也大，先不做 |

顺序：C → A → B → 贴边长出来 → bot 改 Rive，D 等 R2 的跨岛联动确定要做再评估。

## 3. A · 舞台窗口 + 鼠标穿透

**做法**
1. 岛窗口按「展开卡片的最大尺寸 + 阴影余量」一次性定好大小（例如 460 × 竖向最大高度），之后只在切换停靠边、拖动时改位置，形变期间不再调用 `resize_island`。
2. 窗口默认 `set_ignore_cursor_events(true)`，鼠标直接穿过透明区域点到下面的程序。仓库里 `tray_summary.rs:369` 已经这样用过。
3. 命中检测放在后端：`island_pointer.rs` 已经在用 `GetCursorPos` 轮询鼠标（给视线跟随用）。前端把岛当前的轮廓矩形（含圆角）每次变化时报给后端，后端判断鼠标是否落在轮廓内，在里面就 `set_ignore_cursor_events(false)`，离开就切回 `true`。
4. 轮询频率分两档：鼠标在岛附近（轮廓外扩 40px）时 60Hz，远离时 4Hz，避免空转耗电。

**收益**：形变全程只有 CSS / Canvas 在动，原生窗口不动，不会再有卡帧和边缘切；阴影、光晕、溢出的粒子（R2 的彩带、传球）都有地方画。

**注意**
- 拖动、贴边吸附仍走 `dock.rs` 现有逻辑，只是窗口尺寸固定。停靠时窗口要能贴到屏幕边缘，所以舞台在停靠方向上不留余量。
- 透明窗口更大，DWM 合成的面积会变大，但只在有动画的帧上重绘，静止时没有额外开销。要在真机上看一下 GPU 占用。
- 首次安装引导、`FIRST_INSTALL_INTRO` 这类依赖窗口高度判断的逻辑要改成依赖「岛的形态」而不是窗口尺寸。

## 4. B · 一个连续的轮廓

**做法**
1. 把「岛的外形」和「岛的内容」分成两层：
   - 轮廓层：一条路径，参数只有宽、高、圆角（用超椭圆 / squircle 圆角，比 CSS `border-radius` 更像硬件）。
   - 内容层：收缩态、展开态的内容都常驻，用透明度、位移和轻微模糊切换，不卸载重建。
2. 轮廓的宽、高、圆角用弹簧驱动（Motion 的 `useSpring`，或 `animate` 一个对象）。弹簧被打断时保留当前速度，连续触发也顺滑。参数用架构文档 `motion/tokens.ts` 里的 `SPRING.island`。
3. 顺序固定为「轮廓先动，内容后到」：轮廓开始变形 80ms 后内容才开始淡入，收回时内容先淡出。内容切换时加 4–6px 的 `filter: blur`，让文字像从岛里浮出来，而不是硬切。
4. 气泡（等额度、多会话计数）用「液体分离」：主体和气泡放在同一个 SVG 里，套 goo 滤镜（`feGaussianBlur` + `feColorMatrix` 提高 alpha 对比），气泡从主体边缘鼓出、拉丝、断开；收回时反过来融进主体。岛只有几百像素宽，SVG 滤镜的开销可以接受；如果真机上掉帧，改用一个小的 WebGL 着色器，用有向距离场的平滑并集画同样的效果。
5. 渲染循环只在有动画时运行，静止时停掉 `requestAnimationFrame`。

## 5. C · 硬件感材质

- **不做假玻璃。** 去掉 `backdrop-filter`。R2 的胶囊浅深色都用深色底，这里更进一步：用接近纯黑（`#0B0E0D`）的实体表面，加一圈 1px、8% 白的内描边和顶部很淡的内高光，看起来像一块硬件，而不是一层半透明贴纸。
- **真实阴影。** 舞台窗口有了余量后，用两层阴影：一层紧贴的短阴影（定形状），一层大半径的淡阴影（定高度）。展开越大，阴影越远。
- **从屏幕边缘长出来（已定，取代 32px 迷你胶囊）。** 贴哪条边，轮廓靠那条边的两个角就变成直角，边缘和屏幕边重合，看起来像从屏幕里伸出来的一块。
  - 四条边都用同一种形态：贴顶 / 贴底时横向展开，左右贴边时竖向展开。现在「只有左右贴边缩成迷你胶囊、上下贴边保持完整胶囊」的区别取消。
  - 收起态：只露出 bot 和两圈额度环，靠边那侧没有圆角、也不投影；另外三边保留圆角和阴影。
  - 探出：悬停 400ms 后沿离开屏幕边的方向长出完整内容，轮廓是同一条路径在长，不再换成另一个胶囊。
  - 拖离边缘后，直角在拖动过程中平滑变回圆角，回到自由胶囊。
  - 涉及的现有代码：`dock.rs` 的停靠尺寸计算，`CapsuleIsland.tsx` 里迷你胶囊那一支（`data-small`），`capsule.css` 的贴边规则；R2-I-03「贴边迷你胶囊」一栏的画法要按这条改。
- **光晕跟状态走。** bot 眼睛的颜色在岛的下边缘投一圈很淡的同色光（写入时绿、预警时橙），用 CSS `radial-gradient`，不用滤镜。
- 如果以后确实想要真实的桌面模糊：Windows 11 的 Acrylic / Mica 是 DWM 给整个窗口矩形加的背景，形状只能是矩形（或系统小圆角），和胶囊形状冲突。只在展开卡片是圆角矩形时才可能用，收益不大，不建议优先做。

## 6. bot 的表现（已定：Rive）

bot 改用 Rive 实现。Rive 文件里画 bot 和它的状态机，前端只负责把真实状态喂进去。表情之间的过渡、眨眼、转头、道具出场都在 Rive 里做，比在 SVG 里手写路径插值自然，也能做转身、抖动这类复杂动作。不用 Lottie：它播放的是录好的动画，不适合由实时数据驱动。

### 6.1 分工

| 归谁 | 内容 |
|---|---|
| `botExpression.ts`（不变） | 决定「现在是哪个表情」。规则仍然是表情只由真实状态推出、同一时刻只显示优先级最高的一个 |
| Rive 文件 | 决定「这个表情长什么样、怎么从上一个表情变过来」 |
| `Bot.tsx`（改写） | 把状态喂给 Rive 状态机的输入，不再自己画眼睛 |

额度环不放进 Rive：两圈环仍由前端用 SVG 画（数值要精确、可悬停可点击，R2 的额度交互都在环上），Rive 只画环里面的脸和道具。

### 6.2 状态机输入（Rive 文件与代码的契约）

| 输入 | 类型 | 取值 / 来源 |
|---|---|---|
| `expr` | 数字 | 对应 `BotExpr` 的 16 个表情，顺序固定写在 `lib/botExpression.ts` 的一张表里，Rive 与代码共用这张表 |
| `gazeX` / `gazeY` | 数字（-1～1） | `useGaze` / `botGaze.ts` 现有的视线结果，含窗口外跟随（`island_pointer.rs`） |
| `eyeTone` | 数字 | 0 白、1 绿（写入）、2 青（转发）、3 橙（预警 / 等待）、4 红（出错）、5 灰（睡着）。也可以改由前端给 Rive 传颜色，Rive 支持的话优先传颜色，和 `pn-capsule-*` 变量保持同一份 |
| `prop` | 数字 | R2-I-05 的道具：0 无、1 礼物、2 充能、3 彩带、4 存钱罐、5 餐具、6 旗子、7 咖啡、8 奖章 |
| `poke` | 触发器 | 单击 bot（R2-I-06 戳一戳） |
| `shot` | 触发器 + `shotKind` 数字 | 一次性表情：happy、surprise、greet、reset（对应 `BotShot`） |
| `small` | 布尔 | 贴边收起态（脸缩小，不画道具） |
| `reduced` | 布尔 | 减少动效：开启时状态机直接跳到目标表情的最终帧，不播过渡 |

表情和道具的编号表是两边的唯一契约。加一个表情时，先在 `botExpression.ts` 的表里加一行，再在 Rive 里加对应状态，加一条测试比对两边的数量（与 `agentPage.test.mjs` 比对接线表同一做法）。

### 6.3 资源与加载

- `.riv` 文件放在 `frontend/src/island/assets/bot.riv`，打包进应用，不从网络加载。母版另存一份在 `docs/logo/`（与品牌人物母版放在一起）。
- 运行时用 Rive 官方的 React 包，渲染器选 Canvas 版即可（岛只有几十像素到 140px，WebGL 版没有明显收益）。具体包名、版本和 API 动手前用 Context7 核对。
- Rive 运行时是 WASM。只在浮动灵动岛窗口加载，主窗口的「灵动岛」页预览也按需加载，不进主窗口首屏。
- Rive 加载失败时回退到现在的 SVG 眼睛（`Bot.tsx` 的 `EYES` 表保留作为兜底），并在诊断日志里记一条，不影响额度环和其他内容。

### 6.4 设计侧要交付的东西

- 16 个表情状态（与 `BOT_NAMES` 一一对应）和它们之间的过渡，眼睛只用形状表达，不加嘴巴（R2 讨论已定）。
- 视线跟随：`gazeX` / `gazeY` 驱动眼睛与脸的轻微偏移。
- 8 个道具的出场与收起，道具出现约 1.5 秒后自动收起。
- 戳一戳：单击眨眼、连戳 3 次挤眼（`> <`），告警表情期间不响应（这条由前端控制，不给 Rive 发 `poke`）。
- 浅色、深色两套颜色，或者把颜色做成输入由前端传。
- 交付时附一张输入说明，和 6.2 的表对齐。

### 6.5 迁移

1. 先用 Rive 复刻现有 16 个表情，接入 `Bot.tsx`，表情库预览面板（`IslandExprLab`）逐个对照，确认和现在的行为一致。
2. 再加 R2-I-05 的道具和 R2-I-06 的戳一戳。
3. 稳定后删掉 SVG 眼睛的绘制代码，只留加载失败时的兜底。

## 7. D · 单一叠加层（远期）

每块显示器建一个全屏、透明、置顶、默认穿透的窗口，本体和所有分身都画在同一个画布里，命中检测同第 3 节。

- 好处：R2-I-03 / I-05 的跨岛动画（流量去向、接力传球）可以直接画；N 个分身只占一个 WebView，内存不再随分身数增长。
- 风险：
  - 全屏置顶窗口和全屏游戏、演示软件的冲突要单独处理（检测前台全屏时隐藏）。
  - 多显示器、不同 DPI 要每块屏一个窗口，跨屏拖动要在两个窗口之间交接。
  - 穿透切换只要有一次没切回来，就会挡住用户点击，必须有兜底（例如鼠标离开轮廓 200ms 后强制恢复穿透）。
- 结论：先把 A 做稳，确认跨岛动画真的要做，再评估 D。

## 8. 实施顺序与验证

1. **C 材质**：只改 `capsule.css`，去掉 `backdrop-filter`，换实体表面与阴影。验证：浅色、深色桌面壁纸各截一次图对照 R2-I-01。
2. **A 舞台窗口**：
   - 后端：岛窗口固定尺寸、默认穿透、`island_pointer` 加命中检测。
   - 前端：报告轮廓矩形，`useIslandWindowSize` 退役。
   - 验证：连续双击展开 / 收回 20 次不出现边缘切；鼠标在透明区域能点到下面的窗口；贴四条边各试一次；分身同样生效。
3. **B 连续轮廓**：轮廓层 + 内容常驻 + 弹簧 + 气泡分离。验证：请求开始后 100ms 内改道（打断动画），轮廓不顿；减少动效开启时直接切到终态。
4. **贴边长出来**：按第 5 节替换 32px 迷你胶囊。验证：四条边各贴一次，收起态靠边一侧无圆角无阴影，悬停 400ms 探出、移开收回，拖离边缘时直角平滑变回圆角。
5. **bot 改 Rive**：按 6.5 的三步走。验证：表情库预览面板（`IslandExprLab`）逐个切换，和现在的 16 个表情行为一致；断开 `.riv` 文件时能回退到 SVG 眼睛。

每一步都能单独上线。经典样式（A2）不受影响，只改胶囊样式。

测试范围（舞台窗口带来的）：置顶与「灵动岛置顶」开关、拖动与四边吸附、多显示器与不同 DPI、分身、全屏程序在前台时、透明区域的点击穿透、穿透状态卡住时的兜底恢复。
